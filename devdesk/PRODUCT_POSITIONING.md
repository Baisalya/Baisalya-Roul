# DevDesk product positioning

## Purpose

DevDesk helps a person keep planning, writing, connected knowledge, project
files, API work, and relevant Git context around one folder they own.

It is deliberately useful before someone knows Markdown or developer concepts.
Advanced features appear when the workspace profile or selected file makes them
relevant.

## Primary message

**One folder. Every view. Every tool. Still your files.**

Supporting sentence:

> Plan, write, connect ideas, test APIs, and inspect project Git in one portable
> workspace—without an account, file lock-in, or rebuilding after clone.

## Defensible USP

Do not claim “no other app has any of these features.” Individual products can
offer local files, graphs, project views, developer workspaces, or API testing.

The distinctive DevDesk proposition is the complete combination:

1. ordinary user-owned files remain canonical;
2. normal items become List, Board, Calendar, Timeline, Outline, Files, and
   Relationships without duplicate source records;
3. the folder carries safe identity and relative configuration through
   `project.devdesk`;
4. sanitized API workspace structure and project documentation can travel with
   Git while protected values remain local;
5. a parent Git repository may be detected while DevDesk mutations remain
   strictly bounded to the selected nested workspace;
6. project changes can be Manual, Review changes, or bounded Safe automatic.

## Audience messages

### Everyday user

“Begin with tasks and notes. DevDesk handles structure and relationships for
you. See the same work in the view that makes sense today.”

Benefits:

- useful starters for personal, study, business, and writing work;
- no frontmatter, JSON, node, edge, or OKF knowledge required;
- one place for deadlines, notes, meetings, decisions, sources, and drafts;
- an accessible relationship List when the graph is not the best interface.

### Developer

“Keep project docs, API collections, OpenAPI, JSON, knowledge links, and
workspace-scoped Git beside the code or docs they describe.”

Benefits:

- exact selected-file context follows specialist tools;
- nested folders remain browsable and creatable;
- a sanitized API artifact is created or reopened automatically;
- copy or clone, open `project.devdesk`, and continue;
- parent-repository Git never broadens the selected workspace boundary.

## Trust messages

- No required DevDesk account.
- No DevDesk-operated project-folder upload or sync.
- No silent replacement of existing paths.
- No portable tokens, passwords, cookies, or execution trust by default.
- No claim that automatic rules invent sources, verification, or project facts.
- No unreleased platform presented as available.

## Store-ready copy

Google Play short description, under 80 characters:

> Plan, connect, test APIs, and keep every workspace as ordinary local files

Alternative:

> One portable folder for plans, knowledge, API testing, and project tools

Future App Store subtitle, under 30 characters:

> Your files. Every view.

First description sentence:

> DevDesk turns one ordinary folder into a portable workspace for everyday
> plans, connected knowledge, API testing, and project tools.

## Message guardrails

Use:

- portable;
- ordinary files;
- user-owned folder;
- no required account;
- safe or bounded automation;
- workspace-scoped Git;
- sanitized portable API structure.

Avoid:

- “the only app” or “no competitor exists”;
- “fully offline” when API requests and external links use the network;
- “encrypted project” when ordinary workspace files are not automatically
  encrypted;
- “sync” for copy, Git, or local rebuild;
- “AI-powered” for deterministic OKF and graph maintenance;
- “available on iOS/macOS” before a real signed release.

## Research basis

The positioning was checked against current official product documentation:

- VS Code workspaces emphasise editor folders and relative workspace settings:
  https://code.visualstudio.com/docs/editing/workspaces/multi-root-workspaces
- Postman workspaces emphasise API collaboration and a single source of truth:
  https://learning.postman.com/docs/collaborating-in-postman/using-workspaces/overview/
- Notion project guidance emphasises multiple views over one project database:
  https://www.notion.com/help/guides/project-management-that-evolves-with-your-team
- Anytype describes encrypted local-first objects and a graph:
  https://doc.anytype.io/anytype-docs
- Logseq describes a Markdown/Org knowledge graph:
  https://docs.logseq.com/

These products solve real problems. DevDesk should win through a clear combined
workflow and trustworthy execution, not an unverifiable exclusivity claim.
