# DevDesk store banner, screenshot, and poster prompts

These prompts are ready to paste into ChatGPT image generation. Attach the real
DevDesk logo and the exact current app screenshots before using prompts that
mention them.

## Non-negotiable visual direction

- premium dark navy and midnight-indigo background;
- DevDesk violet as the main accent, with restrained cyan and mint status light;
- clean rounded panels, thin luminous relationship curves, spacious layout;
- one recognisable folder as the visual anchor;
- everyday planning on the left, portable files in the centre, developer tools
  on the right;
- calm, capable, trustworthy—not cyberpunk, gaming, or cluttered;
- no third-party logos, store badges, fake awards, fake ratings, or “#1” claims;
- no invented app screens or altered values inside supplied screenshots;
- no tiny body text;
- no device model that implies an unreleased platform;
- keep important content away from crop edges.

Generate artwork without text when possible, then add the exact approved overlay
copy in a design editor. Image generators can misspell product copy.

## 1. Google Play feature graphic

Required export: **1024 x 500 px**, JPEG or 24-bit PNG without transparency.

Paste this prompt:

> Create a premium Google Play feature graphic for an app named DevDesk, exactly
> 1024 by 500 pixels. Use a deep midnight-navy to indigo gradient with luminous
> violet accents and small mint status highlights. At the visual centre, show
> one elegant ordinary project folder made of layered paper and subtle glass,
> clearly remaining a real folder rather than a cloud database. From that same
> folder, flow a clean task board, calendar, note card, outline, and graceful
> relationship graph on the left; on the right, flow a compact API request panel,
> JSON braces, OpenAPI document, diff marks, and a narrowly bounded Git branch.
> Connect everything with thin professional curves, never thick rods. The story
> is one user-owned folder becoming many useful views and tools. Keep the main
> focal point in the central safe area, keep edges atmospheric only, use large
> simple shapes readable on a phone, and leave calm negative space for a short
> headline. No device mockups, no store badge, no third-party logos, no people,
> no fake UI text, no ranking, award, pricing, or download claim, no pure black
> or pure white background, no clutter. Brand mood: precise, portable, calm,
> trustworthy, professional software.

Preferred overlay:

> One folder. Every view. Still your files.

Alt text, under 140 characters:

> One project folder opens into planning views, connected notes, API tools, and
> scoped Git.

## 3. Google Play phone screenshot system

Recommended working export: **1080 x 1920 px**, portrait, 9:16. Prepare at least
four; this storyboard uses six. Use actual screenshots from the current Android
build.

Use this master prompt once per screenshot:

> Create one 1080 by 1920 Google Play screenshot composition for DevDesk. Use the
> supplied real Android screenshot unchanged as the largest visual element. Do
> not redraw, retouch, invent, crop away controls, or alter any text or data
> inside the app UI. Place it on a premium dark navy to indigo brand background
> with subtle violet glow, restrained mint accents, and a clean rounded frame
> without depicting a specific phone model. Reserve no more than the top 18
> percent for one short, large, high-contrast benefit line. Keep the UI readable
> and dominant. Add only a few abstract folder, curve, or grid motifs behind the
> screenshot. No third-party logos, store badges, fake awards, prices, ratings,
> calls to download, hands, people, or tiny paragraphs.

Storyboard and exact overlays:

1. Home/new workspace screenshot  
   **One folder. Every view.**
2. Board or Calendar screenshot  
   **Plan in the view that fits.**
3. Relationships screenshot  
   **Connect ideas without the clutter.**
4. Workspace status or Files screenshot  
   **Copy or clone. Open and continue.**
5. API testing screenshot  
   **API tools beside your project.**
6. Suggested changes or portability screenshot  
   **Your files. Your control.**

Benefit balance:

- screenshots 1–3 speak to normal users;
- screenshots 4–6 prove portable/developer value;
- the first three should communicate the product without requiring the long
  description.

## Quality and policy checklist

- Compare every framed screenshot with the current shipped UI.
- Export Google Play feature art at exactly 1024 x 500 with no alpha.
- Use at least four high-resolution Play screenshots for strong merchandising;
  keep the real UI prominent.
- Keep screenshot taglines below roughly 20 percent of image area.
- Localize every added tagline for each supported store language.
- Never use “best,” “#1,” “top,” “new,” price, award, download-count, or
  install/download call-to-action claims in Play assets.
- Add accurate alt text.
- For Apple, use actual app UI, no alpha, and a currently accepted device size.
- Do not publish iOS/macOS artwork as availability proof before a real release.
