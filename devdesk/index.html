Why DevDesk

Your work should not be trapped inside the tool that helps you see it.

DevDesk keeps ordinary project files as the source of truth, then gives them useful views, relationships, portability, and optional specialist tools. The distinctive value is the complete combination, not a claim that every individual feature is unique.

Work your way

See the same task, note, goal, meeting, or decision as a list, table, cards, board, calendar, timeline, outline, map, or relationship.

Keep ownership

Your content stays in the folder you chose. Open it in another editor, back it up normally, and share only the files you approve.

Grow without moving

Add connected Markdown, portable Visual Canvas, JSON, OpenAPI, saved API testing, OKF checks, Diff, and workspace-scoped Git as needed.

Portable by design

Three steps from this device to the next.

  1. 1

    Choose or create a folder

    Preview a new workspace, or open an existing folder without writes. Add portable identity only when you choose it.

  2. 2

    Work with ordinary files

    DevDesk derives views and relationships. Safe project writes stay reviewable, bounded, and conflict-aware.

  3. 3

    Copy or clone and reopen

    Open project.devdesk. Local registration and indexes are rebuilt; protected values and trust stay device-local.

Trust before automation

Helpful does not mean hidden.

Read-only indexes can rebuild automatically. Project writes use Manual, Review changes, or bounded Safe automatic mode. Secrets, cookies, execution trust, recents, and personal layout do not belong in portable project files.

No silent overwrite

Existing paths and external file changes are preserved and reported.

No portable secrets by default

Sanitized API structure can travel; protected values stay on the device.

No surprise Git scope

File actions stay inside the workspace. Local commits remain explicit and require a final staged-index review.
