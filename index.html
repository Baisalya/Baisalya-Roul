About

Software engineering with a product mindset.

My work sits between product design and implementation: understand the workflow, reduce unnecessary complexity, then build the software so it remains dependable in everyday use.

I work primarily with Flutter and Android, and I also build Windows and web experiences around the products I ship. The current software in this repository spans developer tooling, shop operations, construction workflows, teacher tools, notification history, and field documentation.

A recurring theme across these products is ownership: ordinary files where possible, offline or local-first workflows where they matter, and product surfaces that explain what the software actually does rather than hiding behind feature lists.

Engineering

Engineering choices shaped by the work, not a technology checklist.

I work across product structure, application behavior, local data, platform delivery, and release hardening. The emphasis changes by product, but the goal stays the same: software that is understandable, recoverable, and dependable in everyday use.

01

Application engineering

Cross-platform product delivery

Flutter-based applications for Android and Windows, with platform behavior treated as part of the product rather than as a final packaging step.

  • Flutter & Dart application architecture
  • Android interaction and release surfaces
  • Windows desktop workflows and distribution
02

Data & resilience

Offline and local-first systems

Products such as DevDesk, ShopPilot, Construction ERP, and NotiVault are designed around local ownership, offline continuity, recovery, or device-first storage where the workflow calls for it.

  • SQLite and device-local persistence
  • Backup, restore, recovery, and migration thinking
  • Ordinary-file workflows where appropriate
03

Workflow design

Operational software, not isolated screens

I structure interfaces around the work that has to move through them: billing, inventory, project operations, field evidence, teaching tools, API workspaces, and documentation.

  • Task and information-flow modelling
  • Dense desktop and touch-first mobile surfaces
  • Clear states, actions, and recovery paths
04

Release engineering

Shipping includes the reliability work.

Validation scripts, documentation, privacy/support surfaces, platform-specific release checks, and regression protection are treated as engineering deliverables.

  • Automated release-content validation
  • Regression and reference-integrity checks
  • Manuals, support, privacy, and release surfaces
