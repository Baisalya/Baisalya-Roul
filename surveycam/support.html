SurveyCam support

Help with field capture and proof reports.

Use the sections below for the common SurveyCam workflow. For app-specific support, email the developer.

Start a field record

Choose or create the relevant project/site category, then capture the photo or video you need for the record.

Choose watermark details

SurveyCam supports address, coordinates, date/time, altitude, compass direction, notes and other field details in the overlay.

Create a proof report

Select the photos you want to document and create a PDF report with the available project and proof information.

Need direct support?

Email baishalya1999@gmail.com and include the app version, Android version, what you were trying to do, and the exact issue.

Before another capture

Find the cause without losing the record.

Start with a fictional test capture so you can repeat the problem without sharing a private project.

Location is missing or looks wrong

Confirm Android location services and SurveyCam's location permission are enabled. If only approximate location is allowed, review whether that meets the task. Move to an open area and wait for a usable fix before capturing again. Compare the displayed position with the location you are actually visiting; an overlay is not a survey-grade measurement.

Date or watermark differs from expectations

Check device date, time and time-zone settings, then review the selected overlay fields before taking a new photo. Inspect the saved capture, not just the camera preview. Keep an earlier record when documenting a correction and state what changed; do not present a corrected timestamp as proof of an earlier event.

A capture is missing from a report

Confirm you selected the intended project and photographs. Create a small report with two test photos, enter a recognizable project title and add a description for each. Open the exported PDF outside SurveyCam and check both photos, order and captions. If the small report succeeds, compare it with the larger selection to isolate the failing input.

Saving or sharing fails

Check available device storage and the selected save destination. Try a new filename and open the saved PDF before invoking the receiving app. If the PDF opens locally but another app rejects it, note that distinction in your support request. Keep your original captures and an independent copy of important reports; avoid clearing app data as a first troubleshooting step.

Send a reproducible support request

Include SurveyCam version, Android version, device model, the operation that failed, expected result and the exact error. Describe whether a two-photo test reproduces it. Remove faces, coordinates and private project information from any sample you choose to share. For a complete example of photo selection, observation notes and handover review, read Turn site photos into a useful field report.
