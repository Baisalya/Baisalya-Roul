Prepare a readable document for an upload limit

A worked PaperAid workflow for cropping a scan, checking page order and reducing file size without losing readable text.

By Baishalya Roul · Updated 18 October 2026

An upload portal can reject a document even when it looks fine in a phone gallery. It may require a particular file type, a maximum size and readable pages in a specific order. This guide uses a fictional application asking for a PDF smaller than 1 MB. The example is a workflow, not a rule for any government or passport service. Read your actual portal's requirements first.

Write down the receiving requirements

Record the accepted format, size limit, page count and whether several documents must be submitted separately. A photo size in pixels and a file size in KB describe different things. Likewise, a PDF upload limit says nothing about how many pages the receiver expects. Keep a copy of the original scan so a failed export does not leave you without a readable source.

Install PaperAid from Google Play on Android or use its Microsoft Store listing on Windows. Both platforms are publicly released. Android can capture with the camera; on Windows, select the source images. The manual covers the current tool controls.

Make the source readable before compressing

For the fictional two-page application, place each sheet flat under even light. Keep fingers, reflections and heavy shadows out of the text. Capture the whole page, then crop to its edges without removing a signature, page number or stamp. If small writing is blurred in the source, recapture it. Compression cannot reconstruct missing detail.

In Scan document, choose the appropriate color or cleanup treatment and review fine text. A black-and-white style can help some printed forms but may remove faint marks or color information that matters. Choose the version that preserves the required information rather than assuming stronger cleanup is always better.

Build one PDF in the intended order

Use Photo to PDF when combining existing images. Arrange the pages so the first application page appears before the signature page, choose the intended page size and export a new PDF. Give it a recognizable name such as example-application-reviewed.pdf. The name should help you select the right file later; avoid including unnecessary personal identifiers.

Open the exported PDF in another viewer. Check the number of pages, orientation and order. Read small text at normal viewing size, then inspect signatures and page edges. A successful save only establishes that a file was written; this review establishes whether the intended information survived.

Reduce size only as far as the task needs

If the PDF is over the fictional 1 MB limit, use a PDF size-reduction tool on a copy. Check the actual saved byte size rather than relying on a filename or an estimated target. A portal may interpret its limit differently, so leave some room below the maximum. Compare the reduced copy against the original, especially small print and light handwriting.

Review the exact file you will submit

Select the reviewed copy, then use the portal's preview where available to confirm it is the intended document. Keep the original and the final copy until the receiving process is complete. Do not delete the source merely because the upload button reported success.

For an ID-photo submission, separately verify the receiving authority's current framing, dimensions and background rules. A PaperAid preset helps prepare an image; it does not guarantee acceptance. For product help, use PaperAid support and include the platform, app version, operation and error message without attaching a private document by default.
